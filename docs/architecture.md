# Architecture

The browser talks only to a loopback Fastify backend. Provider credentials live in that backend's memory or process environment. `server/providers.ts` normalizes OpenAI Responses, Anthropic Messages, and DeepSeek, Gemini, and Qwen Chat Completions streams, tool calls, usage, cancellation, and sanitized errors. Provider destinations are fixed HTTPS URLs, with allowlisted Alibaba regional endpoints for Qwen. Redirects are rejected. Gemini thought signatures are preserved through tool rounds. CLI keys persist in a gitignored, owner-only `.env` file loaded on startup; UI keys and endpoint overrides are session-only. `server/key-file.ts` performs atomic key-file updates and excludes key values from status output.

`server/ai.ts` orchestrates bounded tool rounds for both editing modes. Every run has an ID, editing mode, document/project scope, captured file/revision/selection, state, and usage. Scope is enforced on initial context, listing, reading, searching, diagnostics, and proposals. Ordinary `text` events populate chat only; a validated `type_text` tool produces a separate `typing` event with the resolved range and source text. Replacement targets must match exactly once in the captured active-file revision. No edit action means no document mutation. Autosaved progress must be a prefix of the validated insertion. A project-wide server lock rejects competing source mutations in both modes while allowing reads; Manual Type also reserves its target until progress is finalized. A 45-second heartbeat lease cancels abandoned typing runs. A server restart marks active runs interrupted. Manual Type's network generation is independent of `src/typing.ts`'s grapheme buffer and local delays. The final pending grapheme is held until the next fragment or end-of-stream so split combining characters and emoji stay intact. Stop discards uninserted buffered text. CodeMirror composition history groups the run into one undo event across pauses.

`src/typing-document.ts` keeps the captured source, range, file revision, and saved content independent of the file currently displayed. The destination CodeMirror instance stays mounted while typing, including when hidden, so animation and Undo grouping never follow a newly opened tab. Late autosave responses update its revision without replacing newer visible text. Only the target file receives progress; other files remain inspectable. Read-only transaction filtering rejects typing, paste, deletion, and keyboard Undo while allowing internal AI updates. A stable selection preview displays the submitted passage during a run.

`src/typing-undo.ts` coordinates named recovery from any inspected file: save that file, read the target revision, request Undo, confirm the latest target and mount its restored source/selection with validated CodeMirror history. Valid cached history preserves earlier Undo and one typing Redo; missing history reconstructs that single Redo. The backend commits source and run Undo metadata atomically and returns the same restoration on retry only while its exact revision remains current. Failed or ambiguous responses retain the captured target/history for explicit retry; later source changes reject. Recovery never writes target content into the inspected file or makes a provider request.

`server/store.ts` uses transactions for file revisions, checkpoints, and multi-file patch validation/application. Ordinary content changes materialize files with a unique atomic-write temporary filename. The additive file_disk_state table records the observed disk base and pending write intent before source commits. Startup skips matching files, adopts external indexed bytes/deletions with before/after checkpoints, and replays a committed write only while its recorded disk base still matches. Active source operations refuse disk mismatches. Unsafe filesystem states block only their project; unindexed files remain untouched. [Recovery algorithm, evidence and limits](verification/disk-recovery.md). File moves and renames use the staged-tree transaction described below. Deletion/restoration increments revisions; checkpoints capture the current file revisions. Patch Undo refuses to replace subsequent user edits.

`server/compiler.ts` takes a fresh snapshot for every job, runs `latexmk` with a sanitized environment inside a deny-default macOS sandbox, and persists job IDs and metadata. It retains successful PDFs independently of current source generation. Cancellation targets the subprocess group. PDF and SyncTeX endpoints refer to immutable job IDs. Missing Biber is detected before spawning for biblatex projects that require it. `server/diagnostics.ts` derives final-pass TeX/bibliography diagnostics from bounded confined artifacts, with latest-rule console fallback and tool/lifecycle errors, deduplication, error priority and managed-source location mapping. Version 2 metadata refreshes older latest/requested builds lazily without changing compilation identity or source/history; late IPC cannot mutate finished logs. Unknown formats remain inspectable in raw/generated logs. [Evidence and limits](verification/compiler-diagnostics.md).

`server/tex-runtimes.ts` discovers the System-selected installation, installed Darwin TeX Live `bin/<architecture>` directories and optional backend `PRISM_TEX_BIN_DIRS`. It probes the installed `pdftex --version` with a minimal environment and caches canonical paths, stable IDs, tool availability and filesystem fingerprints. System has a separate identity from a pinned version even when both refer to one directory. Explicit refresh or restart rescans; user/project source cannot register executable paths. Browser settings accept catalog IDs only. Installed runtimes are trusted local software; source confinement does not make an arbitrary configured binary trustworthy.

`runtimeId` is an optional compile-option field; omission means System for legacy clients/jobs. An older client omitting it when saving other options preserves a current pinned choice. New/copy/template projects use System defaults. A build records the resolved label, version, directory and fingerprint, uses its tools/environment, and rechecks the installation before promoting output. Missing tools, changed file identities or repointed tool links require explicit recovery. SyncTeX uses the matching recorded runtime, refusing a missing or changed installation; older jobs without runtime metadata retain legacy SyncTeX behavior and are marked out of date when compared with a current fingerprint. This metadata is not included in source ZIPs/history.

The fourth engine uses application-owned `latexmk -pdfps` routing for LaTeX/DVI/PostScript/PDF. Preflight requires latex/dvips and Ghostscript gs/ps2pdf before creating a job. Runtime resources and selected Homebrew support resources are added read-only to the macOS profile; build output/home remain the only writable directories. The sanitized environment fixes `GS_OPTIONS=-dSAFER` and still excludes credentials, user TeX overrides and imported compiler configuration. After owner-authorized Ghostscript 10.08.0 installation, actual EPS conversion, Normal/draft and error handling, ZIP/SyncTeX, outside-read denial and cancellation during the actual Ghostscript stage pass. This is one physical TeX installation, not historical multi-version compatibility certification. See [runtime verification](verification/tex-runtimes.md) and [package provenance](verification/ghostscript.md).

`server/compiler-supervisor.mjs` owns each new build's POSIX group and optional configured deadline independently of the backend. It launches the confined compiler in that same group only after the backend atomically records its identity and sends the start message. The trusted helper runs through an absolute Node executable without inherited loaders, Node options or API credentials; the compiler retains the minimal environment, disabled shell escape/configuration and macOS profile. Losing backend IPC terminates the group. TERM-resistant descendants receive KILL after one second, including the still-live group anchor, avoiding delayed signals to a recycled leader PID. Cleanup remains armed when journal writes fail. UTF-8 output is bounded to 1 MB and streamed locally; private atomic metadata/results live outside the compiler's writable out/home.

`server/supervision.ts` validates bounded journals and observes groups without signaling saved PIDs. Stop remains running until actual non-zombie group members have exited. On restart, supervised active jobs stay busy until cleanup is observed, then fail conservatively without exposing interrupted PDFs, even when an earlier usable PDF was seeded in their output. A missing/failed process observation is not evidence of drain. Legacy jobs without supervision metadata retain conservative interrupted-failure behavior; their old orphan processes cannot be reconstructed. Graceful app close awaits `compiler.shutdown()` before closing storage. [Lifecycle evidence and limits](verification/compiler-owner-exit.md).

Compile options live in SQLite settings under `compiler:<projectId>` with their own revision. Legacy/missing options resolve to Normal/Stop. Requests capture that revision, reject stale launch choices, and freeze the selected options in each job. `compileArguments` owns the fixed `latexmk -norc` flags, disabled shell escape, Stop's `-halt-on-error`, Continue's `-f`, and graphics draft preamble; imported compiler configuration stays disabled. Continue retains a failed status even when a regular, confined PDF with a valid header exists. The main preview can show that latest terminal error PDF with an explicit label, or the last successful job; a later stop/fatal/cancel falls back to the successful PDF. Options/source-generation mismatches mark the view stale. The debounced auto-compile effect uses stable run-lock state, so chat polling cannot continually reset it; it suspends during typing and avoids repeating the same failed generation/options.

`server/build-files.ts` exposes only finished build output and the matching immutable source snapshot. It rejects symlinks, hardlinks, non-regular files, unsafe paths, changed identities and excessive entry/byte counts. Text preview requires complete strict UTF-8 without NUL and at most 512 KiB. ZIP review hashes selected file bytes and paths, requires consent for differing output/source collisions, and rechecks that hash before preparing a download. Replacements occur only in the derived ZIP. Prepared archives freeze bytes in a four-entry/200-MiB memory cache, expire after 15 minutes or restart, and use native HTTP attachment links with no-store headers. A stale/expired link explains preparation recovery. UI success distinguishes preparation and a requested browser download from an observed save. These reads and exports do not mutate source, checkpoints, review or chats.

The compile-options and generated-files dialogs are lazy components in `BuildTools.tsx`, with native modal focus containment, persistent headings/build identity and fixed action footers. Selection, inspection and ZIP review have separate states and stale-response guards. Their CSS loads with the app so PDF mode/error labels are available before a dialog first opens. Read-only generated-file browsing remains available while AI owns a project; compile-option writes remain locked. Manual Type compilation inherits current project options into its separate preview job, while template preview uses the default options.

ZIP import has an archive-specific path normalizer: harmless `.` segments are removed before the existing managed-file validator runs. Parent/absolute/protected paths, symlinks, encryption, and size violations remain errors, including on entries that would otherwise be skipped. Hidden and macOS metadata entries are reported without opening their data streams. `POST /api/import` retains the project response fields and adds `skippedEntries: { path, reason }[]`; it does not create projects from metadata-only archives. The browser presents a centered file-picker/drop dialog with inline errors, busy state, and a skipped-entry summary after success.

## PDF viewer

`PdfPreview` lays out every page in a continuous vertical stack using exact PDF.js dimensions, including mixed paper sizes and rotation. `src/pdf-layout.ts` converts PDF points to CSS pixels at 96/72, so 100% means the actual PDF-to-CSS scale. Numeric zoom accepts 10–400%; presets are 50%, 75%, 100%, 150%, 200% and 400%. Fit width uses the widest page, and fit height uses the tallest page across the continuous document, rather than changing scale for the current page. Both account for viewer padding. A stable horizontal scrollbar gutter prevents fit-height feedback when a rotated page crosses the horizontal-overflow threshold.

Only pages near the viewport render canvases; offscreen pages retain their dimensions so scrolling does not change layout. Scroll events update the visible-page counter once per animation frame. A page-relative anchor preserves reading position during zoom, panel resizing and recompilation. Canvas rasterization is capped at an 8,192-pixel side and 16,777,216 total pixels, while CSS dimensions, text and SyncTeX geometry retain the requested scale. Render tasks cancel on unmount/scale changes, and each scale gets a fresh canvas. New SyncTeX requests scroll to the requested page and position; forward and inverse navigation use the page viewport's rotation/crop transforms. Forward scrolling keeps short pages visible instead of entering the next page. A validated page-number form supports direct navigation; the focused page region also handles Up/Down, Page Up/Down and Home/End. When several complete pages fit at low zoom, an explicitly selected page stays current while fully visible, including after direct entry, SyncTeX, Home/End or returning from presentation. Ordinary overlap tracking resumes once that page is no longer fully visible; overlap ties ignore rounding differences up to 0.01 CSS pixels.

The controls inherit the compact neutral dark/light editor: existing surface, text, border and focus tokens, muted icon buttons and small rounded fields. `PdfFindBar` opens inline below the toolbar with match controls, pressed option buttons and a live status. `PdfZoomControl` uses a toolbar-anchored, scrollable popover bounded by the viewer's available height; selecting a value or pressing Escape returns focus to its trigger. The toolbar and search options wrap within their panel. The whole editor retains its incumbent desktop-width layout and can pan horizontally on narrow screens; this extension does not establish a mobile editor redesign. Viewer-scoped Cmd/Ctrl+F opens search, Cmd/Ctrl+G steps matches, Cmd/Ctrl plus/minus changes zoom, and Cmd/Ctrl+0/9 selects fit width/height. Source editing and chat keep their existing interaction paths.

`PdfSearchIndex` extracts all pages locally through PDF.js independently of mounted canvases and caches the completed index only for that document. Matching runs in a disposable browser worker through `pdf-search-client.ts`, with cancellation on query/option changes or close. It is literal search within each page, with case, whole-word and accent options. A normalization projection handles compatibility forms and ligatures, optional accent folding, repeated whitespace, line-end hyphenation and Han line breaks. Each normalized UTF-16 unit maps back to the complete extracted source grapheme and PDF text item, so highlights use original text offsets. `PdfPage` draws pointer-transparent highlight rectangles over the unchanged TextLayer, prioritizes the current result and scrolls it into view. This preserves drag selection and double-click source navigation.

Search indexing is bounded to 8,388,608 extracted characters, 500,000 items and 15 seconds; queries are limited to 512 characters and each page's source/normalized projection to 2,097,152 UTF-16 units. Matching has a 15-second deadline inside a worker with a 20-second outer timeout and rejects more than 10,000 matches or more than 2,000 text-item parts in one match. A page displays at most 5,000 highlight rectangles with an omission notice; every returned match remains navigable. Loading, no-match, no-extractable-text and limit failures appear in the inline status. Search starts no provider request and writes no source, revisions or history.

`PdfLinks` reads PDF.js link annotations, compiled outlines and named/explicit destinations without using the full PDF.js viewer or executing annotation actions. Public viewport transforms map rectangle/quad hit regions through crop and rotation. The pointer-transparent `PdfLinkLayer` keeps native text selection intact while providing named keyboard-focusable anchors. A primary click with no drag or selected range follows a hit region; a drag never follows it, and double-click source navigation applies outside links. External anchors allow only HTTP/HTTPS/mailto without URL credentials, use a separate target and `noopener noreferrer`; script, local-file, attachment and form actions remain unsupported. XYZ, Fit/FitB, FitH/FitBH, FitV/FitBV and FitR destinations validate coordinates and preserve explicit zero/null semantics. Presentation resolves internal destinations to a fitted page.

Metadata limits are 10,000 raw annotations, 2,000 links, 5,000 quads and 2 MiB label/destination text per page; 2,000 bookmarks, 32 nested levels and 512 KiB outline titles. Labels truncate on grapheme boundaries. Document-local caches retain four annotation pages and 256 destinations with an eight-second deadline, caller cancellation, retry after failure and disposal on PDF replacement. `PdfBookmarks` supplies native nested lists, collapse buttons, loading/error/empty states and a sticky close header. `PdfViewHistory` retains at most 100 in-memory reading snapshots, including page-relative vertical position, horizontal offset, zoom mode and preferred page. Previous/Next View and named history actions restore these independently of source history; a new compiled PDF clears them. Navigation operations abort on newer navigation, scrolling, zooming, SyncTeX and unmount so late destinations cannot override the reader. This implementation does not add PDF form editing, comments, file attachments, OCR or tagged-document semantics.

A scoped PDF.js TextLayer overlays nearby canvases. Selection pins its page range while canvases remain virtualized; zoom updates the same text nodes. Copy clips native ranges to PDF spans/line breaks and normalizes Unicode ligatures, excluding placeholders and application text. Select All followed by Copy extracts all pages through a separate document-local memory cache. Extraction streams serially with character/item/time budgets, cancellation and disposal guards. Read PDF text supplies a read-only text area, including within isolated draft previews; Escape closes only the innermost dialog. This supplies basic readable text access, not OCR, tagged-PDF semantics, guaranteed semantic reading order or a complete screen-reader PDF viewer. Geometry styles adapted from PDF.js retain their Apache-2.0 notice in `vendor/pdfjs`.

`PdfPresentation` portals a native modal dialog inside a fullscreen host, allowing it to appear above an already-modal compiled Manual Type draft. It fits one page at a time, hides editor chrome and provides page buttons, keyboard/wheel navigation and Escape exit. Focus stays in the presentation and returns to its opener on close; the continuous viewer resumes at the last presented page. Native fullscreen is requested when available, with window presentation retained after rejection or an immediate fullscreen exit. Window presentation is visually verified; sustained native-fullscreen visual behavior remains unproven in the in-app browser. Presentation does not imply broader Overleaf parity.

`App` marks the last successful PDF stale when the build generation differs, autosave is pending, or partial Manual Type text is visible. The partial-typing condition retains the banner even after that visible progress has autosaved; viewing or searching the immutable build does not update its source snapshot.

## CLI backends

`server/cli.ts` runs the installed Codex CLI or Claude Code through their non-interactive JSONL interfaces. These are separate provider IDs (`codex`, `claude-code`) from the five API adapters. The backend inherits only a small environment allowlist needed to find the CLI and its normal login; API keys, provider redirects, proxy settings, and executable-code environment overrides are excluded. Leaf never opens credential files or forwards tokens to the browser.

Each command gets a disposable directory under `data/cli-runs`. Context is supplied on stdin. Native CLI tools and user/project customizations are disabled; Codex also receives a read-only workspace permission profile and disabled tool-network access. Organization-managed policies still apply. Review responses contain a validated envelope of Leaf tool requests, executed by the existing project/revision layer. CLI output cannot directly mutate project files. Manual Type uses the same validated tool envelope, with chat text and typing payloads kept separate, and retains the lock, autosave, stop, and undo lifecycle. Its single edit may follow read-only project inspection rounds.

Login checks are cancellable and run after the AI-run ID is created, so Stop also works during preflight. Generation has a three-minute timeout, 2 MB stdout guard, completion-event validation, and process-group termination with escalation. Codex emits completed messages; Claude emits incremental text deltas. The CLI protocol does not provide the API's hard output-token cap. CLI selection preserves the requested model and reports subscription usage without a guessed API price. No automatic fallback is configured. See [CLI protocol notes](cli-backends.md).

The shared model picker keys every option by provider/connection plus model ID. Only connected sources contribute choices; API lists exclude retired and non-composer model families. Codex discovery uses a short-lived stdio app-server with only `initialize`, `initialized`, and paginated `model/list` requests, never a thread or turn. It uses the CLI's own model catalog (which may be cached), not extracted credentials. Claude Code exposes supported family aliases with plan-access labeling. API pricing remains a separate versioned catalog; dynamically discovered models without known prices require explicit selection for Manual Type.

## Conversation, draft, and history foundations

SQLite `conversations` group runs across requests. API messages replay bounded, scope-filtered turns including edit payloads and outcomes. The context estimate includes this history. Native CLI sessions are resumed by exact ID with the same isolation flags; their working directories are keyed by conversation/provider/model/scope/file under `data/cli-sessions`. IDs stay in backend conversation metadata and are omitted from list responses. Current source and current scope are supplied on each turn. Recent successful CLI connection checks are reused for five minutes; explicit Refresh still checks again. No automatic provider/model fallback or paid retry was added.

`server/chat-drafts.ts` stores unsent prompts in a separate additive SQLite table, keyed by project and conversation (an empty conversation key is the New conversation slot). Versioned, idempotent writes do not touch source, project history or native sessions; cleared rows retain monotonic revisions. The browser's `DraftController` serializes per-key saves and reconciles late responses, ambiguous success and explicit competing-window choices. Local keepalive saves and beforeunload protection reduce pending-text loss without claiming abrupt-crash durability before commit. Optional `AiRequest.draftRevision` binds the exact submitted text; conversation selection, the accepted run and draft consumption commit together. Legacy clients omit that field and do not consume unrelated drafts. Prompt errors stay local to the draft UI; source context/model/scope remain current composer choices, not draft metadata.

The browser requests `previewFirst` for Manual Type. A run moves from generation to `preview`, retaining its file reservation and lease, and accepts no progress until explicit approval. Draft edits are held in the preview workspace. `/approve` validates the original revision, approves the edited payload, and transitions to typing. `/compile-preview` overlays the draft onto an immutable compile snapshot without saving files. Preview jobs are excluded from project build listings and last-successful-PDF selection. Failed draft builds show logs without changing source. New editor views show an active-run recovery banner and can reopen a waiting preview without generation. A backend restart interrupts pending runs; it never submits a request automatically.

Automatic checkpoints batch ordinary edits after 10 seconds idle with a 60-second maximum. AI boundaries and shutdown flush pending changes. Every project receives an initial version; existing databases migrate additively and legacy chats become separate saved conversations. Checkpoint file bodies use SHA-256-addressed blobs so unchanged binary assets are stored once. Legacy inline-base64 checkpoints remain restorable. Snapshot metadata remains in SQLite and ordinary file revisions are still the durable autosave layer. History currently retains all entries; no pruning is implicit.

Undo chooses CodeMirror history when available, preserving ordinary Undo/Redo. Per-file serialized history and selection survive tab switches, keyed by project and file; a source mismatch discards the cache. After reopening a file, the server's revision-bound Undo restores source and selection without adding a reversed edit to native history. Competing user edits invalidate the server shortcut. Shutdown interrupts active AI work and releases source locks before closing storage.


The history workspace compares current or saved source snapshots by file, reports additions/deletions/content and compiler-setting changes, and serves textual source differences separately from binary assets. Historical source exports resolve deduplicated blobs or legacy base64 bodies. File restoration checks the current revision and path-tree compatibility, backs up the project, updates only the selected file with a new revision, and materializes it through the same managed-file boundary. Whole-project restoration remains available. Version labels update metadata without changing source or snapshot contents.

Additional history APIs: `GET /api/projects/:id/checkpoints/:checkpoint/compare?target=...`, `/file?path=...&target=...`, `/export`; `PATCH /api/projects/:id/checkpoints/:checkpoint` for a label; `POST .../restore-preview` prepares a scope-bound plan before `POST .../restore-file` or `POST .../restore`. Confirmation requires an operation UUID, exact preview token, source revision/generation and, when restoring review, the current review token. A missing comparison `target` means the current saved project.


## Local references, completion, and word count

`shared/project-intelligence.ts` scans BibTeX entries (braced/quoted fields, nested braces, strings and concatenation), manual bibliographies, biblatex `.bbl` entries, and LaTeX labels. Comments and common verbatim environments are excluded. Reference search normalizes accents and matches key/title/author/year/journal. Source paths and line numbers remain attached to entries, and duplicate/incomplete-entry diagnostics are returned. `.bib` metadata takes precedence over generated entries with the same key. This is a static source index, not arbitrary TeX macro evaluation. The backend caches by project generation and caps indexed source at 16 MB.

CodeMirror uses a project-aware completion source with read-only gating. Citation and label replacements stop at their argument boundaries; command snippets preserve existing arguments. The References window captures a source selection, rejects changed targets or invalid boundary-spanning selections, and makes one normal Undo event for insertion. No provider or network service is involved.

`server/word-count.ts` runs unmodified, bundled TeXcount 3.1.1 via system Perl. Each job copies managed text into an immutable analysis snapshot and uses the existing macOS deny-default compiler sandbox and credential-free environment. Imported scripts and TeX commands are never executed by the counter. Limits: 32 MB text, 15 seconds, 1 MB output, and two concurrent jobs. Snapshots are removed afterward. A generated `.bbl` may be overlaid only from a successful normal build whose source generation matches the snapshot. The result carries that generation so the UI can indicate staleness. Categories and section summaries are parsed from the native report, which remains available for warnings and custom `%TC` rules. The app bundles TeXcount and its license under `vendor/texcount`; it does not install a system utility.

Local APIs: `GET /api/projects/:id/intelligence` and `POST /api/projects/:id/word-count` with optional `{includeBibliography:true}`. These share existing loopback/origin checks and managed-project boundaries.

## Source formatting and insertion

`src/source-actions.ts` produces bounded source replacements and explicit selections. `sourceEditTransaction` dispatches them as isolated CodeMirror history events through the existing read-only transaction filter. Toolbar clicks and editor shortcuts use the same action path. Heading changes preserve stars, optional short titles, nested commands, and trailing comments. Dialogs capture a project, file, source, and range; insertion rejects changed targets. Normal autosave and automatic history observe only applied edits, not draft form changes. A figure upload is a separate ordinary project-file addition.

The table builder generates core `tabular` source with plain-text escaping or explicit LaTeX cells; it accepts up to 30 × 12 cells, per-column alignment, rules, captions and labels. The figure builder references managed PNG/JPEG/PDF assets with `graphicx` (required in the preamble), width and float placement controls. Unsupported or unsafe graphics filenames are rejected. The local symbol catalog has 88 entries with aliases and package hints. Standard math-delimiter detection suggests whether inline delimiters are needed; users can override it for custom macros. Filtering keeps selection within the visible results and disables insertion for an empty search. No AI request is involved in these tools.

## Source-backed visual editing
