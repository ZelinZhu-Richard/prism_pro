# Replacement preview compilation recovery

This worktree closes a Prism-specific reliability gap around the owner's reviewed Manual Type workflow. The replacement's compiler now has its own Stop control and recoverable status, separate from AI generation and source insertion. Overleaf's official [compilation guide](https://docs.overleaf.com/getting-started/recompiling-your-project) was refreshed on 2026-11-01 for its auto-compile, draft and error-handling behavior; this report does not attribute Prism's replacement-preview workflow to that product.

A SQLite `preview_build_requests` journal binds a run, explicit local request ID, replacement hash and owned compile-job ID. Repeating the same request returns its original job; changed text under the same identity is rejected. A Stop arriving before its delayed Start leaves a persistent cancellation marker and prevents the late request from starting a compiler. Compiler metadata contains the same ownership identity, allowing a journal update lost after job creation to recover the existing job. Status reads do not launch compilation or generation. The journal stores hashes and identifiers, not API keys or the replacement text.

Cancellation keeps an actual process **running with cancelRequested** until its close event, then marks it Cancelled. This prevents a second build from starting during the termination interval and prevents cancelled PDF promotion. Escalation timers are cleared when the child exits. The regular build's Stop remains available while an AI preview holds source locks; ordinary compilation itself still respects those locks. Discard, AI Stop, lease release and orderly shutdown cancel owned replacement builds. Approval rejects an active or draining preview build.

The client captures one request and replacement, guards asynchronous results by request generation and command, and retains locked recovery controls when a start/poll/cancel response is uncertain. Retry reads status before reusing the exact Start identity; it cannot silently start a different replacement. A fresh view can reopen saved build status without generating or recompiling. A result belonging to an earlier replacement is labelled. Edited unapproved replacement text and suggestions remain session-only; confirmed source insertion and chat prompt drafts retain their separately documented persistence.

They cover exact request replay, cancellation-before-start, mismatch/source-revision rejection, owned-run cancellation, process-drain approval locks, journal restart/repair, origin/request validation, delayed hashes/polls/errors, lost successful starts and cancellation retry. Vite retains its existing chunk-size advisory.

It checked source/history neutrality, idempotent replay, cancellation-before-start, no overlapping build while draining, last ordinary PDF retention and exact snapshot text. No TeX dependencies were installed. Evidence: ignored `data/verification/preview-builds-real.log`, `preview-builds-fixture.json` and its report directory.

Built-in-browser checks used only synthetic projects on an owned 5173 server; the owner's 4317 process was untouched. No live provider, CLI or paid request occurred.
