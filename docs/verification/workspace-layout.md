## Persistence and failure behavior

Layout values live in a separate, revision-bound SQLite setting, outside source files, source history and ordinary editor preferences. Values are validated as finite bounded dimensions and strict booleans. Saves are serialized and debounced; an older acknowledgment cannot replace newer visible choices. Matching repeats are idempotent. Conflicting views return a conflict rather than overwriting silently.

A failed or ambiguous save keeps the current visible layout, marks the header and offers **Retry saving this layout** or **Load saved layout**. Retry reads the current receipt before writing again. Load saved does not discard a newer view change made during that read. Requests have a bounded deadline; retries and reloads are explicit. Only acknowledged settings are confirmed saved. Pending page-exit saves are best effort; source recovery remains a separate mechanism.

The popover uses native checkboxes, fieldsets and buttons. It opens at the first panel checkbox, Escape returns to Layout, and pointer/keyboard panel resizing remains available. Retry/reload keep focus on the surviving checkbox when recovery buttons disappear. The neutral header and panel materials inherit the existing light/dark themes.

## Boundaries

The saved layout is an application-wide view preference. Open tabs, active source selection and full-browser-restart PDF page/zoom restoration are not delivered here. Unacknowledged view changes may be lost on abrupt termination; source journaling is independent and remains authoritative. Source-only narrow editing is checked; combined Files/source/PDF layouts retain the incumbent desktop minimum and are not full mobile-editor acceptance.

No owner paper, private project, real provider key or owner-server restart was used. Existing AI behavior is retained. Native desktop packaging, external-folder ownership and OS-disconnected/cold-cache acceptance remain separate plan items. Restart the local app when convenient to load the new backend settings routes.
