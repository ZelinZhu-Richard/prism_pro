# Persistent unsent chat drafts

Unsent prompt text is stored locally per project, saved conversation and New conversation, with a 16,000-character limit. Draft-only changes create no AI run, native session, source revision or checkpoint. Source exports and project copies omit them; saved drafts remain available with restored archived conversations or projects. Only prompt text is captured; model, scope and source selection remain current composer choices.

The backend checks project/conversation ownership and monotonic draft revisions. Exact retry identifiers are idempotent; stale or conflicting writes preserve the local text for explicit comparison. Cleared rows retain a revision tombstone. On submission, optional `draftRevision` binds the exact prompt; creating/selecting the conversation, recording the run and clearing that draft commit in one SQLite transaction. Failed starts retain the draft. Accepted runs keep their submitted prompt in saved history, including when subsequent provider generation fails. Older clients without draft metadata do not clear unrelated unsent prompts.

The browser debounces saves by 400 ms, flushes before chat/project navigation, uses local keepalive requests on pagehide and warns about pending work on beforeunload. It guards active keys against late reads/saves, preserves exact retry requests after lost successes, and explicitly resolves two-window drafts. Wait for **Draft saved locally** for confirmed persistence; an abrupt crash before the commit can lose pending text. Neither reload nor draft recovery automatically submits an AI request.
