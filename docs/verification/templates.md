## Scope and limits

Snapshot limits are 100 MiB / 5,000 entries, 100 active / 500 retained personal templates, and 512 KiB selected UTF-8 text preview. Complete binary/legacy source remains in ZIP/created projects. Content updates require a new snapshot. Trash has no purge, and blobs/history have no pruning. Root candidates are included text `.tex` files; users choose the correct entry point when ambiguous. Preview compilation uses installed packages, max two concurrent template jobs, cancellation and the existing two-minute timeout. Template jobs do not become normal project PDFs or history entries. Closing/switching cancels the owned pending preview; restart never resumes one automatically.

Committed snapshots and operation journals persist; unsent modal fields and pending Retry request IDs are session memory. No online gallery, template publishing, journal submission, dependency installation or distribution/version picker is included. Extreme-size interactive performance, every loading/empty/validation composition, exhaustive assistive-technology behavior and motion are not visually certified.

The static detector ran once on the changed UI targets. It fell back to regex because optional parser modules were unavailable, so computed contrast and selector analysis were not evaluated. It reported only two intentional 16px typography advisories (detail heading/narrow inputs), with no warnings. All captured and shipped rasters carry origin metadata. The independent finish review returned **ship** with no material fixes for all twelve required current captures and sampled UI/editor/library integration. It did not independently read backend implementation, raw test source or built output; supplied test/build/compiler logs and database audits were read without rerunning them. Its verdict does not certify whole-app parity, exhaustive accessibility, motion, every loading/empty/limit state or extreme-content performance.
