# Ordinary folders and recoverable file operations

Leaf opens ordinary folders in place through **Open Folder** on the home page or in the editor’s project menu. The dialog accepts an absolute folder or `.tex` path, shows a bounded inventory and lets the user choose the main document. A review token binds the inventory and directory identity to the open action. The backend rechecks the reviewed bytes and performs metadata-only adoption. A disappeared file aborts adoption and remains missing.

An indexed nested `.tex` file opens in its existing linked project and retains that project’s main document. The project library records **Recently opened** independently of source updates. If the original folder moves, **Locate folder** verifies its identity and retains project history and settings. Opening a replacement folder requires a separate project. A read-only linked folder allows source inspection, snapshot compilation and export.

## Implemented boundary

`ProjectDirectories` records an explicitly captured canonical folder path, device, inode and birth identity separately from document source/history. Existing managed projects retain their old storage shape and locations. A linked project uses the chosen ordinary directory for physical file access; its metadata/history stays in Leaf's application data.

Adoption indexes matching existing source bytes without rewriting files, changing their permissions/modification timestamps or renaming the chosen root. Candidates cannot overlap Leaf data or another available linked project. Path-component comparison includes filesystem roots and normalized spelling, without treating a shared text prefix as a directory boundary. Explicit protected/parent/control/invalid-Unicode paths fail before filesystem lookup; final-component symlink roots and unsafe indexed descendants are refused.

Every linked source-directory resolution revalidates its recorded identity. Missing, moved, replaced, symlinked, unreadable or corrupt bindings fail closed. Startup does not recreate the folder or fall back to a managed source directory. Other projects remain usable. An explicit moved-folder relink requires the original identity, the reviewed source generation and no competing agent owner; it does not silently adopt a replacement folder.

Source saves retain existing atomic write receipts, revision conflicts and recoverable versions. A destination that is read-only at preflight is rejected before a changed source commits or an unnecessary write receipt is created. A filesystem failure after a source commit is retained as a per-project recovery problem instead of crashing startup for all projects. Staging rechecks the bound root, so a replacement folder cannot receive the intended original-folder write merely because its file happens to have the old content hash.

Linked project Trash is metadata-only. Restoring it reconciles external changes before any source write; an unavailable folder stays unavailable and is never recreated. Source ZIPs, independent managed copies, source checkpoints and AI context use indexed relative files; directory binding, hidden configuration and unindexed content do not become source exports or automatic provider context.

## In-place upload, Trash, restore and Undo

Linked uploads, file Trash and restore, and batch Undo now commit their source revisions, history, and recovery intent together in SQLite. Physical replay creates only needed parents, verifies each affected path, and removes directories nonrecursively. Leaf checks reviewed revisions and generation, the original directory identity, and the before and after file hashes. It resumes matching changes before general startup reconciliation. If another editor changes a touched file, the pending batch blocks source mutations and compilation for that project while its original and proposed versions remain in History.

Empty implicit parents can remain after removing their indexed files. The managed tree swap remains restricted to managed projects.

## In-place moves, renames and reference updates

Linked moves commit the operation, indexed source revisions, reviewed reference updates and history in SQLite before changing individual paths. A folder rename carries its unindexed descendants with the same directory and file identities. On case-insensitive volumes, Leaf uses a temporary hop and verifies the actual filename spelling. Replay verifies the expected location and content of each indexed file, including the reference text, before continuing. Undo uses the same guarded operation to restore names and references together.

If replay encounters an outside edit or a new destination, it preserves the physical files and blocks further source writes and builds for that project. After preserving the conflicting item and clearing the conflict, the user can choose **Retry recovery**. The checks cannot provide OS-level exclusion against an arbitrary program racing a filesystem syscall. Leaf’s local browser dialog uses pasted absolute paths. Native chooser and Reveal integration are deferred.

### Destination identity and refreshing a stale review

A linked move stops before committing if its indexed destination folder is missing. New move journals retain the existing destination parent’s filesystem identity. Recovery waits if that parent is missing or replaced, even if the replacement has no file at the destination. Returning the original parent allows the pending move to resume. Previously saved journals can still replay using their original checks.

When the folder inventory changes before Open Folder is confirmed, the dialog announces the conflict and focuses **Refresh review**. The refreshed inventory keeps a still-valid main document selection and requires a separate confirmation. If that selection disappeared, the refreshed default is shown for review.

Two regressions cover missing destinations and replacement parents across restart, retry and Undo. The built-in browser verified keyboard refresh after an outside edit, a real build containing the updated text, and nested `.tex` reopening in the same dark-mode project. It also refused a move into a folder that disappeared during review, then moved and undid the file after the folder was returned. The final disk bytes match the source before the move. Full 883 tests and production build pass. Logs are under `data/verification/leaf-move-open-*.log`, with API receipts in the [offline release fixture](offline.md#linked-folder-release-check).

### Reviewed disk identities and staging conflicts

The browser's linked move and rename previews bind the operation to the reviewed source item and its source and destination parents. Leaf refuses a changed identity before writing history or changing paths. New operations retain the original source-parent identity for Undo, and new recovery journals validate both parents. Existing journals and direct callers that omit a preview token retain their earlier checks. The editor exposes **Retry recovery** or **Locate folder** immediately when a failed move or Undo leaves the project requiring recovery.

For managed projects, Leaf compares the original disk tree against the metadata observed during staging before it installs the new tree. A mismatch rolls the SQLite transaction back and returns the original directory to its location. Reviewed source bytes are checked again in the stage before a move or rename. This covers outside edits during the tree copy. An unrelated program can still race filesystem syscalls, and power-loss durability remains untested.

In the built-in browser, an externally substituted destination triggered a conflict. Returning the original directory allowed a refreshed preview, move and Undo. A folder rename changed `\input{sections/note}` to `\input{parts/note}`, and Undo restored both files and reference text byte for byte. The separate replacement folder retained its sentinel. Focused regressions exercise a replacement parent during Undo across restart, a same-size outside edit after managed staging with its original modification time restored, and an edit before managed staging.
