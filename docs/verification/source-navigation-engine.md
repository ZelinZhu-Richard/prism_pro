# Read-only source-navigation engine

Verified 2026-11-02. This is the engine/API stage of definition/reference navigation. Editor commands, result selection and browser acceptance remain pending; there is no new navigation control to claim as delivered yet.

`POST /api/projects/:id/source-locations` accepts an exact literal command, environment, label or citation name and definitions/references mode. It returns project-relative paths, UTF-16 spans, line numbers, bounded excerpts, source revisions and SHA-256 hashes. All matching duplicate definitions remain inspectable; no TeX load-order winner is inferred. An optional active-file overlay replaces only that file's saved index for this request. It does not save source, create history or adopt disk changes. Differing saved/buffer revisions are explicit. Existing local origin/header/project guards apply, and agent ownership still permits read-only inspection.

The scanner reuses literal declarations and opaque/comment/raw boundaries. It supports standard/xparse command/environment declarations, primitive literal definitions, common label/reference and citation commands, BibTeX records and literal bibitem/biblatex-entry keys. Caret lookup prefers a key or environment name over its surrounding command. BibTeX key offsets come from the existing structured record parser, preserving nested-record exclusions and original Unicode positions. A common expandafter/def/csname idiom is excluded as computed; direct literal redefinition of csname remains recognizable. Comment masking was extracted unchanged into a shared module to avoid a runtime dependency cycle.

This is lexical assistance, not TeX expansion. Macro-definition bodies, dynamic names, catcodes, arbitrary package-specific references, installed package definitions and complete load-order semantics are unsupported. Optional arguments with nested square brackets are not covered by the current reference-key pattern. Paths are taken from managed indexed source; external changes require the existing explicit adoption workflow. Original bytes are never rewritten by navigation. Invalid UTF-8 is skipped with a warning rather than converted by this engine. The separate [editable-source safety repair](source-encoding.md) now blocks lossy reads/writes; this engine continues to skip those bytes explicitly.

Bounds are explicit: 1,048,576 UTF-16 units per TeX/style/class/bbl source, twice that for BibTeX; 20,000 locations per source; 10,000 indexed entries, 2 MiB per file, 16 MiB source and 50,000 saved locations per project; four cached project generations; 2,000 returned matches. Current-file overlay results are separate from the saved-project limit. Warnings disclose truncated/skipped work. Excerpts center around a location, stay within 200 UTF-16 units and do not split surrogate pairs. A generation change during index construction rejects the mixed result before caching. No source or imported script executes.
