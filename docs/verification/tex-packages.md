# Installed TeX filename catalog — 2026-11-02

The backend now exposes read-only installed package/class metadata for the project's explicitly selected TeX runtime. This foundation is now connected to [package-name completion](installed-completion.md); document-class suggestions remain outside that interface.

`GET /api/projects/:id/packages?q=geometry&refresh=1` returns the project ID, compiler-settings revision, runtime snapshot, database source, status/check time/fingerprint, bounded package results, total and warnings. `refresh=1` rechecks metadata; no installation occurs. Names are matched without case sensitivity against names/relative paths, with name-prefix matches first. Each entry keeps its distribution-relative path and `.sty`/`.cls` format, including duplicate names at different paths. Runtime paths cannot be chosen through this endpoint; a missing selected runtime returns an error with no fallback.

The distribution catalog reads the selected installation’s `texmf-dist/ls-R`. It parses safe literal `tex/` filename entries and verifies existing regular files with canonical paths confined to that distribution. It skips document/source trees, unindexed files, unsafe names, missing files and escaping links. A missing, malformed, linked, legacy-byte or oversized database produces an unavailable result. A separately configured personal tree can still supply suggestions.

Work is bounded to an 8 MiB database, 500,000 lines, 20,000 candidate package/class files, metadata batches of 32, four cached installations and 200 matches per response. Cache identity includes runtime tools and database inode/size/timestamps. Unchanged-index metadata is cached for at most 30 seconds, with explicit refresh available; a file removed without updating `ls-R` may remain listed until then. Concurrent same-index normal reads share pending work; refreshed older results cannot replace a newer cache. Returned objects are isolated from caller mutation. These are filename facts from a trusted installation, not a full Kpathsea search-order, engine-compatibility or dependency guarantee.

## Personal TeX trees — 2026-11-06

`LEAF_TEXMFHOME` explicitly selects one absolute local tree for the backend. It defaults to disabled. **Compile options** reports the status. **Refresh runtimes** and explicit package completion refresh the inventory. The browser and imported projects cannot supply the path. The catalog lists package and class files under `tex/` without an `ls-R` database. Package suggestions label personal provenance and retain same-name distribution paths. Project packages keep precedence in the completion list.

Each build reads a bounded inventory from `tex/`, `bibtex/` and `fonts/` and copies stable file bytes into its own read-only `texmf-home` snapshot. Only that snapshot becomes the build’s `TEXMFHOME`. The original folder receives no compiler access grant. Root configuration and the root `ls-R` are excluded, along with hidden or protected paths, links and special files. Capture is limited to 4,000 entries, 16 directory levels, 16 MiB per file and 64 MiB overall. A replaced root or a changing or oversized tree fails before the compiler starts. The captured bytes remain in the build directory and stay outside project source, history and ZIP exports.

The package-content fingerprint guards incremental reuse. The foreground disk check compares observed tree metadata with the last build’s captured metadata and marks the PDF stale when the tree changes. Compile captures a new snapshot. F12 reads recorded personal package definitions from the matching build snapshot. This keeps older excerpts tied to the source the compiler saw. The package catalog supplies filenames, while TeX resolves dependencies and load order during a build. Class suggestions, automatic package installation and user-specific runtime configuration remain outside this feature.
