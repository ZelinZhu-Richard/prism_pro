## Guarded review and retry

The captured review binds project generation and the physical manifest. A changed source or disk tree rejects the entire import before metadata adoption; Refresh retains the intersection of previously selected paths and never silently selects new arrivals. Initial selection and each import are limited to1,000 entries. Lists paginate100 rows at a time with retained cross-page selection and keyboard focus on the new range.

Each import has one UUID and a durable SQLite receipt, written atomically with source metadata, disk receipts and before/after checkpoints including review state. Lost confirmations retain the same request for **Retry import**, including after backend reopen. Replays do not duplicate history, source versions or project generation. A confirmed commit followed by a failed metadata refresh stays retryable. The client aborts an unresponsive transport after15 seconds and ignores late results; aborted transport does not imply a server mutation was canceled. Closing or restarting the app never starts an import or paid request automatically.

Scanning is bounded to10,000 entries,128 MiB total regular-file bytes,100 MiB per file,64 directory levels and100 skipped entries. UTF8 recognized text up to2 MiB is editable; other file bytes are preserved as binary. Hidden/protected names are skipped before traversal, as are unsafe/static links, hard links, devices, path/case/normalization collisions and unindexed Leaf staging artifacts. Directory identity/timestamp checks and no-follow regular-file reads reject observed races. This is managed-folder evidence, not OS confinement or a malicious-local-racer guarantee. Arbitrary folder opening/ownership and automatic file watching remain separate work.
