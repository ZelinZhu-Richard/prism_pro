# Cross-file Manual Type Undo

This local reliability change keeps **Undo typing in [file]** available independently of the inspected tab. It saves pending edits in that tab before restoring the named target, briefly locks mutations, opens the restored file and focuses its original selection. Later target revisions reject recovery. File-level toolbar Undo remains file-specific.

Source and the run's `undone` marker/Undo revision now commit in one SQLite transaction. Repeating the same recovery returns the recorded restoration only while that exact revision and source remain current. A disk-materialization failure can be repaired by retry without another revision. The client retains pre-Undo source and editor history across an ambiguous response, confirms the returned revision against the latest target, and preserves native Undo/Redo where valid. After restart, one typing Redo is reconstructed; earlier browser-only editing history cannot be recovered from an absent cache.

Sixteen regression tests exercise project-wide eligibility, unrelated dirty files, Unicode and original selection, cached earlier Undo/one-event Redo, missing/damaged cache, empty replacement, duplicate clicks, failed saves, stale revisions, project changes, delayed/wrong/legacy responses, lost successes, transactional rollback, disk repair, restart and local-origin HTTP boundaries. The full suite has **496 passing tests**, and TypeScript plus the production Vite build pass. The existing large-bundle warning remains.

Browser verification used only Codex's visible built-in browser, a separate server on port 5173, synthetic source and a deterministic provider stub. The owner's server on 4317 and private papers were untouched. Five requests stayed in one saved conversation: an unapplied preview was discarded; a second run was paused/resumed and stopped while inspecting notes; a third completed run survived an actual test-backend restart plus browser reload; the fourth confirmed the save-status correction; a fifth insertion-only run checked summary refresh and Unicode Redo after reload. No live provider or paid request was used, and Undo/Redo/retry made no generation calls.

Verified behaviors:

- Selected text is visibly retained in the composer. During typing, another file opens read-only and rejects typed input.
- After Stop, a named cross-file Undo saves pending notes, opens the target and restores exact original source and selection. The notes retain their added text.
- One native Redo restores exactly the visible partial text; one Undo returns to original source.
- After backend restart/reload, the completed run remains recoverable from another file without browser history. A deliberately lost successful response leaves a named error, Retry and Dismiss. Keyboard Retry confirms the same source revision; one reconstructed Redo restores the complete insertion.
- A later test repeats lost-success recovery against the final build. Undo/Redo leaves original source marked Saved. Testing exposed and corrected a stale Unsaved indicator when an edit was undone back to saved text; revision changes now also reevaluate pending autosave.
- Dark and light themes were inspected at 1440×1000, reported-user 997×833, short 1280×720 and configured 560×850 (actual capture 553×839). Recovery paths wrap and keyboard focus remains visible. The inherited narrow editor still pans horizontally, and recovery prose/actions scroll within conversation history; this is not a mobile-editor redesign.
