# Project-local LaTeX completion

Verified 2026-11-02. Code view now completes literal commands declared in project `.tex`, `.sty` and `.cls` files, including unsaved declarations in the active file. It also suggests nested project `.sty` packages and package names used elsewhere in the source. Ctrl+Space opens the existing completion menu; accepting a command replaces its name without guessing or adding custom arguments. Existing braces, optional arguments, suffixes and surrounding source remain intact. Current-file declarations replace that file's saved index entries, so a deleted or renamed unsaved declaration does not linger as a suggestion. Editing a declaration does not suggest its own partial name.

Labels show **Local command declaration**, **Project package**, or **Used in project · installation not checked**, with file/line provenance. Package names do not certify installed dependencies or active TeX load order. Current package-load text is excluded from its own candidates. Duplicate command names form one option retaining all indexed locations; a local declaration of a built-in name keeps literal insertion rather than a potentially incompatible built-in snippet. Existing citation, label, environment and standard command suggestions remain available. Read-only source returns no editable completion.

## Boundaries

This is bounded lexical assistance, not TeX expansion. It recognizes standard LaTeX/xparse command declarations and primitive def/gdef/edef/xdef with literal ASCII-letter/@ command names; comments, inline/raw literals and nested definition bodies remain opaque through the existing environment scanner. Dynamic csname expansion, catcodes, arbitrary package-specific declaration syntax and complete TeX semantics are unsupported. Literal headers are useful while editing; they do not prove a definition compiles. Package candidates come from managed project source, not a global installed-package catalog. Go-to-definition remains separate work.

The scanner stops beyond 1,048,576 UTF-16 code units, retains at most 2,000 command declarations and 2,000 package-load records plus a local package filename per file, and uses the incumbent environment token/nesting guards. The saved project index retains up to 10,000 declarations of each kind within its existing 16 MiB source budget and reports limits. Each query offers at most 200 custom command/package options; normal source editing continues. Four immutable document/path results are cached for current-file assistance. Imported source is parsed as text and never executed by completion. Indices follow saved project generation and guarded external-version adoption; observing disk changes does not silently change the indexed source.
